# Changelog

Crab follows [semantic versioning](https://semver.org). Before 1.0, a minor version may break what an application writes; the entry says what to change.

## Unreleased

- **Downloads and a limit on every answer (breaking):** no answer's body may be longer than `http_client.max_bytes`, 64 MiB by default, checked as it arrives, compressed and decompressed alike; a longer one throws `HttpClient\TooLargeException` and its connection is closed. Raise the limit for one call with `request(..., maxBytes:)`, or for the client with the setting or the constructor's `maxBytes:`. `sink:` streams the body of a `2xx` answer into a file that appears only once it is all there, or into a writable stream; `decode: false` keeps a compressed body as the server sent it. `FakeClient` does the same, and takes `maxBytes:`. A transport of your own takes a fifth argument to `exchange()`. See [Downloading files](docs/http-client.md#downloading-files).
- **Services that cannot be made are found before a server starts:** `start`, `reload`, `queue:work`, `schedule:work` and every runner follow what each route's action and named middleware, every listener and every scheduled task, job and command needs from the container, without making any of it, and refuse to start with every problem at once (`Contracts\Container\MissingServices`). A reload that would have failed on its first request now leaves the old server serving. `php cua describe app` lists the same problems. `Container::problem($id)` says why one entry cannot be made, and `App::unmade()` lists them all. See [Services that cannot be made](docs/deployment.md#services-that-cannot-be-made).
- **`status` and `stop` work when the application cannot be loaded:** after a deploy of code with a syntax error or a provider that throws, they act on the server in the background from the files in `storage/`, and every other command says why the application did not load and that the server goes on serving. `--pid` names a pid file other than `storage/crab.pid`. To have this, change the last line of `cua` to `exit(Crab\Cua::run(__DIR__ . '/app.php', array_slice($argv, 1)));`. `Server`'s `pidFile()`, `logFile()`, `statsDirectory()`, `stats()`, `running()`, `stop()` and `given()` moved to `ServerFiles`, which `$server->files()` returns. See [When the new code does not load](docs/deployment.md#when-the-new-code-does-not-load).
- **`describe` labels each problem `problem:`** where it said `does not fit:`, since a problem may now be a service as well as a setting.
- **A readiness recipe:** [Ready for traffic](docs/deployment.md#ready-for-traffic) keeps a probe that asks the database and the cache apart from `/up`, so an outage takes servers out of rotation without restarting them.
- **A running job keeps its reservation:** the worker renews it every third of `queue.retry_after`, so no other worker is given a job that is still running however long it takes, and `retry_after` now bounds only how long a job may block its process. A store of your own implements `renew()` (`Contracts\Queue\Store`).
- **Job timeouts:** `queue.timeout`, a supervisor's `timeout` or `#[Timeout(seconds: 1300)]` on the job bounds one try. When it is up, the `Cancellation` a job's `handle()` takes is cancelled and the try fails with `Contracts\Queue\TimedOut`; a job still running `queue.grace` seconds later has its worker's process ended and replaced. `Worker::deadline()` is the engine's part of that, for any work that must not outlive a limit. See [A job that takes too long](docs/queues.md#a-job-that-takes-too-long).
- **Cursor pagination:** `cursorPaginate($perPage, $cursor)` returns a `Contracts\Database\CursorPage` with the rows after the cursor and `nextCursor` for the page after them, as JSON `data`, `per_page`, `next_cursor`, `has_more`. Rows added or removed meanwhile do not shift the pages, nothing is counted, and the order may be by several columns, an alias of an expression or a grouped column, each in its own direction, with nulls where the database sorts them. An order that does not end with a unique column is refused; a cursor not given for the order is `Contracts\Database\InvalidCursor`, a `422`. See [Cursor pagination](docs/queries.md#cursor-pagination).
- **`Contracts\Http\HttpError`:** an exception that carries the status it is answered with. `HttpException` is one; the error handler answers any of them with its status and message, so a component that must not depend on HTTP can still mark a client's mistake. An error handler of your own should test for `HttpError` where it tested for `HttpException`.
- **Subqueries:** another query stands for a column with `selectSub()`, a condition with `whereExists()` and `whereNotExists()`, a value with `where('price', '>', $query)`, a table to join with `joinSub()` and `leftJoinSub()`, and the table read with `$db->table($query, 'name')`. It may name the outer query's columns, and its values are bound in place. `groupByRaw()` groups by an expression. `Connection::table()` takes an alias, `table('users', 'u')`; a connection of your own adds `?string $as = null`. See [Subqueries](docs/queries.md#subqueries).
- **JSON columns are read at a path** wherever a column is named, `where('data->actor->id', $id)`, with a missing key and JSON's `null` alike to `whereNull()`, and `true` and `false` compared as JSON's. See [JSON columns](docs/queries.md#json-columns).
- **Presence and null are apart (breaking):** as in PHP, a field without a default must be sent, even when its type is nullable: `?string $note` is required and may be null, `?string $note = null` may be left out. In `#[Fields]`, a name ending in `?` may be left out and a type starting with `?` may be null, apart: `'name?' => 'string'` may be left out but never cleared, which is what an update wants. An object or a list described in place is never null. To upgrade, give a nullable field that may be left out a default, `= null`, and in a description move a `?` that meant "optional" to the end of the name.
- **`#[RejectUnknown]`** on an input class, or on described `Data`, refuses a field it does not declare with `is not expected`, where Crab otherwise ignores it. See [Refusing unknown fields](docs/validation.md#refusing-unknown-fields).
- **Rules across fields:** an attribute that implements `Contracts\Validation\ObjectRule`, on a class or on described `Data`, checks the object once its fields are valid and names the field a problem is told against. See [Rules across fields](docs/validation.md#rules-across-fields).
- **A value of several kinds:** a field may be a union of scalar types, `bool|int|string|null`, taken as JSON says; text stays text where `string` is one of them. See [A value of several kinds](docs/validation.md#a-value-of-several-kinds).
- **Each action parameter says where it comes from (breaking):** a plain parameter is a parameter of the path, `#[FromQuery]` (`Crab\Routing\FromQuery`) reads the query string, field by field or as one marked class or described `Data`, and a class or described `Data` without the mark is the body. A body's field is no longer a parameter of its own, and the query string is no longer read in place of the body on `GET`, `HEAD` and `DELETE`, so a field cannot come from the address when the action meant the body. A signature that leaves a source unsaid is refused when the route is added, with what to write instead. To upgrade: mark query fields `#[FromQuery] int $page = 1`, and move a body's fields into an input class or `#[Fields([...])] Data $input`; on a `GET`, mark an input class `#[FromQuery]`. A validation `422` now says where each problem was: `fields` for the body as before, `query` and `path` beside it; `Problem` and `ErrorResponse::make()` take `query:` and `path:`. See [What an action takes](docs/actions.md#what-an-action-takes).
- **`cache:clear` keeps locks:** `clear()` removes this cache's values only, on every store, and leaves its locks and every other `cache.prefix`'s entries. `cache:clear --locks` (`clearLocks()`) also frees locks, for one left by a process that died. Values and locks now live under `value:` and `lock:` keys, and the file store keeps each entry's key, so entries written by an earlier version are read as missing once: the cache starts empty after the upgrade. A store of your own implements `extendIf()` and `clear(string $prefix)`.
- **Locks can be refreshed:** `$lock->refresh($ttl)` holds a lock longer, only while it is still yours, for work whose length you cannot know.
- **`withoutOverlapping()` for scheduled tasks:** a run is not started while another runs on any server, or in the generation a reload replaces. It holds a lease renewed while the run lasts. `onOneServer()`'s claims are locks now, so clearing the cache no longer gives a run to a second server. See [Overlapping runs](docs/scheduling.md#overlapping-runs).
- **Uploads are fields of the body:** declare a file as `public UploadedFileInterface $avatar` in the body's input class, or in described `Data`, and it is checked before the action runs: required unless nullable, an empty file input counting as none, `#[FileSize]` for its bytes and `#[MediaType]` for its kind, read from the content. `#[ListOf(UploadedFileInterface::class)]` takes `photos[]`, and `describe` shows them. See [Uploaded files](docs/requests.md#uploaded-files).
- **The test client sends forms, files and raw bytes:** `Testing\Api`'s `post()`, `put()`, `patch()` and `request()` take `form:`, `files:` and `body:` as the HTTP client does, through the same parser a client's request meets. See [Testing](docs/testing.md#sending-forms-files-and-raw-bytes).
- **File storage:** named disks behind `Contracts\Storage\Disk`, with `local` (the folder `storage/files`, by default) and `memory` for tests. A file is written whole or not at all, read as a stream, listed a page at a time, copied and moved; a path is checked before a disk is touched. `crabphp/s3` adds `s3`, for Amazon S3, Cloudflare R2, MinIO and the rest, on the HTTP client, with signed download and upload URLs. See [File storage](docs/storage.md).
- **Your own error format:** bind `Crab\Contracts\Http\ErrorRenderer` and it writes every error response, returned or thrown: the router's 404 and 405, validation's 422, middleware's 401, 429 and CORS refusals, `HttpException` and a failure's 500, keeping the headers middleware gave them. Replacing the error handler is no longer needed to change the format. `ErrorResponse::make()` takes `cause:` and `debug:` in place of `$detail`.
- **`text()` and `binary()` hold any length on MySQL,** as documented: they create `longtext` and `longblob`, where `text` and `blob` stopped at 64 KB. Tables already created keep their columns; change one with a migration of its own if it needs more.
- **The testing guide's database settings** now match the skeleton (`DB_DRIVER` and `DB_DATABASE`, not `DB_DSN`, which nothing read), and the skeleton's `phpunit.xml` sets them, so tests never reach the development database.

## 0.1.0 — 2026-10-24

The first public release: a long-running JSON API framework with its own engine.

- **Server:** `dev` serves and restarts when a file is saved; `start` serves for production, in the foreground or with `--daemon` in the background, where `reload` replaces it without refusing a connection, keeping the options it was started with. `status` shows every running server, its workers and what each has handled.
- **Settings** are checked when the application starts, against rules declared beside their defaults; every problem is said at once, and `describe app` lists them.
- **Routing, actions and validation** from typed parameters, PSR-7 and PSR-15 middleware, errors as JSON, logging, authentication, cache, events, queues, scheduling, an HTTP client, database queries and migrations, WebSockets and broadcasting.
- **`describe`** prints the whole application for coding agents.
