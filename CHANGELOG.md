# Changelog

Crab follows [semantic versioning](https://semver.org). Before 1.0, a minor version may break what an application writes; the entry says what to change.

## Unreleased

- **The application's time zone (behaviour change):** `app.timezone`, `UTC` unless set, is the zone every date of the application is in: the clock, the database's dates, the logs and the scheduler's times. It used to be whatever `date.timezone` the server's PHP had. An application whose server was not in UTC, and whose stored dates are therefore in that zone, sets `APP_TIMEZONE` to it to keep them meaning what they did.
- **After a rollback:** `Connection::afterRollback()` runs a callback if the transaction that asked, or one around it, is rolled back or loses its connection, and never once the outermost transaction has committed. It is for putting back what code changed in memory for a write that did not happen. When a commit fails without saying whether it happened, such as a connection lost while the database answered, neither `afterRollback()` nor `afterCommit()` callbacks run; when the database answers the COMMIT with an error, as SQLite does for a deferred foreign key, the work was rolled back and `afterRollback()` callbacks run. A class of your own that implements `Contracts\Database\Connection` or `Database`, such as a test double, must add `afterRollback()`.
- **A committed inner transaction keeps its `afterCommit()` callback:** one asked for inside an inner transaction that committed was dropped when a later inner transaction of the same outer one rolled back. It now runs when the outer transaction commits.
- **Date bindings use the default zone (behaviour change):** PDO and async MySQL now write a bound `DateTimeInterface` as the same instant in PHP's default time zone, just as record fields do. A date in another zone no longer writes its own wall-clock time; use the intended instant when binding dates.
- **Ordered chunks are refused:** `chunkById()` reads in ascending order of its cursor column and now refuses any other order, which made it skip rows and repeat others. An `orderBy()` of that same column, ascending, is accepted; remove any other before calling it.
- **`find()` on a query with an `orWhere()`:** the query's own conditions are now taken as one, so that the id asked for is not matched against the last of them alone. `where('a', 1)->orWhere('b', 2)->find(3)` could return a row other than 3.

- **The current loan:** `Database::current()` returns the connection lent to the calling fiber by `run()` or `transaction()`, with nested loans restored on return; outside a loan it returns the database. A class of your own that implements `Contracts\Database\Database`, such as a test double, must add `current()`.
- **Mapping attributes on properties:** `#[Json]` and `#[ColumnName]` may be written on a property as well as a constructor parameter.
- **Shared field conversion:** `Contracts\Database\Field` reads and writes one declared property's value; records keep their existing mapping and messages. The internal `Database\RecordField` is removed.
- **Enums in statements:** PDO and async MySQL bind backed enums by their integer or string value, including conditions and updates without `into()`.

- **Benchmarks live separately:** benchmark fixtures, research and recorded results are removed from the framework. Use [crabphp/benchmarks](https://github.com/crabphp/benchmarks) for performance work and its engine maintainer tools for request-path and soak checks; the framework no longer provides `composer soak`. Historical research remains in Git.
- **TLS for engine protocols:** `Crab::listen(tls: ...)` negotiates implicit TLS before protocol dispatch. `Connection::startTls()` upgrades an existing connection as a server or client, with a bounded handshake and verified clients by default. The protocol owner flushes its positive reply, passes all unread parser bytes to `unread:`, and discards pre-upgrade protocol and authentication state. Engine-created streams have private SSL contexts; an outside stream must supply its own context. See [the engine guide](src/Engine/README.md#tls-and-mail-dns).
- **Local TLS failures are visible:** certificate and private-key files are checked in the worker at listener startup and again for upgrades. Local handshake setup failures report their PHP and OpenSSL reasons through `FailureReporter`; a peer's bad handshake closes quietly. `shutdownWrite()` on an encrypted connection flushes and closes fully: TLS has no half-close here.
- **Explicit DNS lookups:** `DnsResolver::resolveMx()`, `resolveTxt()`, `resolveA()`, `resolveAaaa()` and `resolvePtr()` use bounded asynchronous UDP queries, validate the entire packet, and isolate caches by record type. PTR builds the reverse question from an IP address and validates returned names; A and AAAA methods return only the requested address family.

## 0.6.4 — 2026-11-10

- **Primitives for a TCP relay on the engine:** `Engine\Network\Connector` opens an outbound connection, with TLS when asked, from a task. `Engine\Network\Relay` carries bytes from one connection to another and stops reading the source while the destination is behind, so a slow reader costs one read's worth of memory. `Engine\Server\TcpServer` takes a second callback that is given each accepted connection before its bytes, for a protocol's own state, close and drain handling. `Crab::listen()` takes `maxWriteBufferSize:` and `closeTimeout:` for the connections a listener accepts.

## 0.6.3 — 2026-11-07

- **Quiet cancellation when an HTTP connection ends:** a retired request's own cancellation now ends its handler or streamed response without an unhandled failure report, including a client leaving an event stream. Other cancellations and cleanup failures are still reported, even after the connection closes.

## 0.6.2 — 2026-11-06

- **Cookie authentication for browsers:** `CookieAuth`, bound by `TokenAuthPlugin`, reads the user's database token from an `HttpOnly`, `SameSite=Lax` cookie, named `__Host-auth` over HTTPS so that no sibling subdomain can shadow it, the same token `TokenAuth` reads from a header, so there is still no session. `$auth->cookie($token)` logs a browser in, and `$auth->logout($request)` revokes the token and clears the cookie. Any request that can change something, and any WebSocket handshake, must come from the application's own pages, by the browser's `Sec-Fetch-Site` or `Origin` against `app.url`, so forms need no hidden token. A page can send the browser to a login page instead of answering `401`, and a cookie whose token stopped working is cleared. Its settings are `auth.cookie.*`. See [Cookie authentication](docs/authentication.md#cookie-authentication).
- **Middleware named by class is given its services too:** a `UsesContainer` middleware listed by name, such as `->middleware(CookieAuth::class)`, was made by the container but never passed to `withContainer()`, so a missing plugin was found on the first request instead of at startup. It now goes through `withContainer()` like an object does.

## 0.6.1 — 2026-11-06

- **Faster waiting for a pooled connection:** on one process serving 64 requests at a time, an async MySQL lookup by primary key serves about 11% more requests a second with the default `pool` of 10, where most requests wait in line for a connection, and about 1% more with a pool of 64, where none waits. A pool now keeps one timer for all the callers waiting on it, set again for whoever is to give up next, where each waiting caller had a timer of its own; each still gives up after its full `timeout`. The event loop keeps each fiber's suspension for as long as the fiber lives, where it made one for every wait. Waiting in `Concurrency` and on the HTTP client's connection pools takes the same path. See [the measurements](https://github.com/crabphp/framework/blob/917a2f23c86dd458673e3dc8d1ec63691fd58029/BENCHMARKS.md).

## 0.6.0 — 2026-11-05

- **Runs and actors are packages of their own (breaking for an application that uses them):** they move to [crabphp/runs](https://github.com/crabphp/runs) and [crabphp/actors](https://github.com/crabphp/actors), for the applications that need them, and the framework keeps to what every API uses. Their classes, plugins, commands, settings and tables keep their names. To upgrade, require the package beside the framework, `composer require crabphp/runs` or `crabphp/actors`. `App::OPTIONAL_PLUGINS` no longer lists `RunsPlugin` and `ActorsPlugin`, and `config:publish` no longer writes `runs` or `actors`: their packages' READMEs describe their settings.

## 0.5.0 — 2026-11-05

- **A run is fenced by its claim (breaking for the runs table):** a worker that stalled past `runs.lease` and was overtaken could still renew, complete, fail or release the run another worker had taken, turning a completed run back to pending. Each claim now carries a token, and only its holder may write the run. To upgrade, add a nullable `claim` column of 32 characters to the runs table: `$schema->table('runs', fn (Table $t) => $t->string('claim', 32)->nullable());`. `runs:install` writes it for a new application.
- **A run's waking and retrying survive a queue that is down or slow:** a signal's wake-up only pushes its job, and the run stays waiting until a worker claims it, so a failed push can be mended by sending the signal again and a quick worker's later wait is never overwritten. `retry()` changes nothing itself: it pushes a job whose worker claims the run from failed and starts its tries again, so a push that fails, is lost or never happens leaves the run failed, to retry again. A step an overtaken worker comes to is not kept either. A retry job restarts only the failure it was asked for: a second retry asked meanwhile does nothing, even when the run has failed again by its turn.
- **`runs:recover` gives a job to a run that lost its own:** a run's state is kept before its job is pushed, so a process that died between the two, or a queue that lost the job, left it pending or asleep for good. `Runs::recover()` and the `runs:recover` command push a job for each run pending or sleeping more than `runs.lease` seconds after its time; schedule it, `$schedule->command('runs:recover')->everyMinute()->onOneServer()`. A run that waits out a failed try's backoff now has its `wake_at` set to when the next try is due. A run left running by a worker that died, with no job to take it up, is counted a failed try and tried again, once `queue.retry_after`, or a longer one of a supervisor that takes from the runs' queue, and a lease have passed since its lease ran out, so a worker that only stalled is not counted dead. `retry()` of a run left running marks it failed first, under a claim of its own, so that recovery cannot count its try again before the retry's job comes and the stalled worker, should it go on, can write nothing more. Every write a worker makes to its run now needs the run to be running under its claim. A job that comes before a run is due, during a backoff or a sleep, no longer takes it early: it comes back when the run is due.

- **A cookie is never set for a public suffix:** `CookieJar` took any domain with a dot, so `https://attacker.co.uk/` could set a cookie for `co.uk` that went to every site there, and one `github.io` site for the rest. It now checks the Public Suffix List, shipped in `src/HttpClient/data/` under the Mozilla Public License 2.0, as RFC 6265 asks.
- **A compressed body cut short is refused:** a gzip or deflate answer that ended before its stream did was returned as a success, and a download moved over the file at its path. Its decoder must now reach the stream's end; a cut body fails, leaves the old file, and a streamed reader is told rather than handed a quiet end.
- **A deflate body is read whatever piece its first byte comes in:** whether it has zlib's header was judged from the first piece alone, and a one-byte piece made a valid body fail.
- **A request's header replaces the client's whatever its case:** a client's `Authorization` and a call's `authorization` were both sent; the call's now wins.

- **A pool's replacement is never lent to no one:** `Pool::discard()` chose the waiter before making the replacement, and one that left while it was made lost it, leaving it counted as borrowed forever. Who gets it is decided once it is made: a waiter then, or the idle ones. Its place also stays taken while the old resource is cleaned up, so a cleanup that waits can no longer let a newcomer in and the pool lend more than its limit. A replacement that cannot be made is told to the first waiter, and the place, kept, is tried again for the next, so none is left waiting behind a newcomer.
- **An actor's first `ask()` keeps to its timeout and cancellation:** it waited for the reply channel to be ready first, for as long as that took. That wait now counts against its timeout and ends with its cancellation, without giving up the channel other asks share. Sending the message no longer holds it either: a carrier slow to publish cannot keep an ask past its timeout or cancellation, and an ask that ended before it was sent is not sent. Messages for an actor in another process are published in the order sent: a remote ask takes its place in line when it is made, and a `tell()` after it waits for it to be published, or withdrawn by its timeout or cancellation.
- **A command's children stop with it on macOS too:** `Engine\Process\Subprocess` and `Process` start a command in a process group of its own, so that a timeout, cancellation or output limit stops everything it started. They used `setsid`, which macOS does not have; there they now use perl, which it always has. Linux still uses `setsid`, and without the posix extension a command still runs without a group of its own.

- **Faster database reads and validated requests:** on one process, a lookup by id in SQLite serves about 26% more requests a second, a validated JSON `POST` about 23% more, and a MySQL lookup 6–8% more; nothing that is not on those paths changed speed. A query's limit is now written into its SQL rather than bound, as SQLite planned a bound limit again on every run; its offset stays bound. The query builder keeps one grammar per driver and each quoted name, `Database`'s query methods borrow a connection without a closure each, an everyday email address is checked without `filter_var()`, which still decides every other one, ASCII text's length is its byte count, a header field is found with a plain search and only once per request, a JSON or form body is parsed without making a stream of it first, and an `int` route parameter of plain digits is read without patterns. See [the measurements](https://github.com/crabphp/framework/blob/917a2f23c86dd458673e3dc8d1ec63691fd58029/BENCHMARKS.md).
- **Faster JSON and text responses:** on one process, `GET /hello` serves about 6% more requests a second and a validated JSON `POST` about 3% more. A JSON or text response without other fields is copied from a blank one rather than constructed, takes its fields from a constant array, and hands the engine its own constant fields, which it knows by identity and has already encoded; nothing is allocated for its fields any more. See [the measurements](https://github.com/crabphp/framework/blob/917a2f23c86dd458673e3dc8d1ec63691fd58029/BENCHMARKS.md).
- **Faster async MySQL:** with `async` on, a lookup by primary key serves about 6% more requests a second on one process. The driver reads each packet from its buffer in one call, sends a command of one packet without a generator, asks an idle plain connection whether it is still alive with one peek where it made two system calls, and asks whether an empty read was a closed connection only after waiting for it. [Database](docs/database.md#not-blocking-the-worker) now says how to size `pool` for the requests a worker serves at once.

## 0.4.0 — 2026-11-04

- **Plugins, in place of providers (breaking):** a provider is now called a plugin. `Contracts\Provider` is `Contracts\Plugin`, `WorkerProvider` is `WorkerPlugin`, `withProviders()` is `withPlugins()` with the same `remove:` and `only:`, `App::PROVIDERS` is `App::PLUGINS`, and every framework `*Provider` class is a `*Plugin` (`QueueProvider` → `QueuePlugin`, and so on). The application's own provider is its setup: the skeleton's `app/Providers/AppProvider.php` is `app/Setup.php`, class `App\Setup`, given to `->withSetup(Setup::class)` in `app.php`, which registers it after every plugin. See [Services and plugins](docs/plugins.md).
- **Core and optional plugins (breaking):** only the core plugins are on without being listed: database, auth, cache, storage, events and the HTTP client (`App::PLUGINS`). The queue, the schedule, runs, broadcasting and actors are optional, like token authentication already was (`App::OPTIONAL_PLUGINS`). To upgrade, list the ones the application uses in `app.php`, in this order: `->withPlugins([QueuePlugin::class, SchedulePlugin::class, RunsPlugin::class, BroadcastPlugin::class, ActorsPlugin::class, ...])->withSetup(Setup::class)`. A framework plugin named twice, core or optional, is registered once.
- **A listed plugin's server runs with `start` (breaking):** `server.with` is gone. `start` runs, beside HTTP, every server registered: the queue's workers when `QueuePlugin` is listed, the scheduler for `SchedulePlugin`, the actors for `ActorsPlugin` when the broadcast carrier is not the local one, and any your setup registers. To upgrade, delete `with` from `config/server.php` and the `SERVER_QUEUE`/`SERVER_SCHEDULE` lines from `.env`; a configuration that still sets it is refused at startup as a setting that does not exist. Every machine that starts the application now runs its scheduler, so with several, mark tasks `onOneServer()`. `describe` no longer says whether a server is on.
- **One way to send bytes on a socket (breaking):** `Socket::sendBinary($bytes)` is gone; send `new Binary($bytes)` with `send()`, in an action and on a `TestSocket` alike. `Crab\WebSocket\Binary`, an alias, is gone too: import `Crab\Contracts\WebSocket\Binary`.
- **`config:publish storage`** writes the storage section, which had no file to publish.
- **A run's data is checked as a job's is:** `Runs::start()` now refuses a value of the wrong type for its parameter and a `handle()` taking a class such as `DateTimeImmutable`, where the worker failed later. Text that is not UTF-8 is refused where a job is pushed or a run started, rather than by the store.
- **A run's data cannot be named `$run`:** `start()` takes that name itself, so such a run is refused with a message saying so, where PHP's own error came before.
- **An invalid WebSocket ticket is challenged as the header way is:** `Ticket` answered `WWW-Authenticate: Bearer` whatever scheme `TokenAuth` was given; it now uses `TokenAuth::challenge()`.
- **Fewer queries:** `Runs::latest()` reads its runs and all their steps in two queries, where it made two for each run, and the database queue's `counts()`, which the dashboard asks for, in one where it made four.
- **`stop --force` no longer leaves the pid file now and then:** telling whether the server had ended raced with its parent collecting it, and could answer that it was still running.
- **`Async::sleep($loop, 0)`** resumes on the next turn of the loop, as it says, rather than through a zero-second timer.
- **Less engine (breaking for code using these):** UDP (`Crab::udp()`, `UdpEndpoint`, `UdpServer`), `Worker::connect()` with `Network\Connector`, and `Async\ConnectionStream` are removed; nothing in the framework or its packages used them. Outbound connections are made by the clients that need them (HTTP, MySQL, Redis). `Worker::stats()` no longer has `pendingConnects` or `datagrams`.
- **For commands of your own:** `Input::value('name', example: '…')` returns an option's value and refuses `--name` given without one, with the message the framework's commands use. `Migrator::install($name, $contents)` writes a package's migration among the application's unless one of that name is there, which is what every `*:install` command does; a migrator of your own implements both (`Contracts\Console\Input`, `Contracts\Database\Migrator`).
- `Contracts\Schedule\Task` has `preventsOverlaps()`, which `describe` already used.

## 0.3.0 — 2026-11-03

- **A storage directory that can be moved:** everything the framework writes, logs, `server.pid` and its stats, the file cache, the `local` disk, is in one folder, `storage/` unless `->withStorage($dir)` in `app.php` or the `CRAB_STORAGE` environment variable says otherwise. A relative path starting with `storage/` in a setting is inside it, `storage_path('database.sqlite')` names a file in it from a configuration file, and `app.storage` reads it. To upgrade, replace `dirname(__DIR__) . '/storage/...'` in configuration files with `storage_path('...')`. A SQLite file whose folder is missing has it made. See [Storage elsewhere](docs/deployment.md#storage-elsewhere).
- **A single executable:** an application packed into a phar and appended to static-php-cli's `micro.sfx` runs as one file: its `.env` and storage are beside the file, configuration and migrations are read from inside the phar, and `start`, `reload`, `restart`, servers kept across reloads and servers that run a command work as they do under `php`. See [A single executable](docs/deployment.md#a-single-executable).
- **An idle timeout for streamed answers:** `$http->stream(..., idle: 60.0)` gives up on a server that sends nothing for that many seconds, waiting for the answer's head or between reads of its body, with a `NetworkException`, while `timeout()` may be raised to the longest a whole answer may take. A client of your own implementing `Contracts\HttpClient\Client` adds `?float $idle = null` to `stream()`. See [Streaming answers](docs/http-client.md#streaming-answers).
- **Commands that do not block the loop:** `Engine\Process\Subprocess::run(['git', 'status'], directory:, environment:, input:, timeout:, maxBytes:, cancellation:)` runs a command while other tasks keep running and returns its exit code, standard output and error, and whether it timed out or wrote past its limit. A cancellation, timeout or output limit kills it, and with `setsid` and the posix extension present so is everything it started, so a background child never outlives it.
- **Stricter at the edges (breaking for some):** `Runtime::onSignal()` refuses `SIGINT`, `SIGTERM` and `SIGUSR1`, which stop and reload the server, where a callback for one used to replace shutdown. A local disk refuses a path through a symbolic link inside its folder and `files()` leaves links out. The HTTP server answers `400` to an absolute-form target or `Host` whose port is past 65535 or whose authority is malformed. The HTTP client refuses an answer, over HTTP/1.1 and HTTP/2 and from `FakeClient` alike, whose `Content-Length` is not a number or whose values disagree, whose `Transfer-Encoding` is anything but `chunked` or comes with a `Content-Length`, or whose status is outside 100–599. A timer, `everySeconds()` or a queued job's data refuses `NAN` and `INF`, and a job or run whose `handle()` takes the `Cancellation` or `Run` twice is refused when pushed or started rather than failing in the worker.

## 0.2.0 — 2026-10-30

- **Actors:** a class with `handle(Inbox $inbox, string $key)` runs once for each key, takes its messages one at a time in the order sent, and keeps its memory in its variables until `actors.idle` seconds without a message. `Contracts\Actors\Actors::tell()` returns at once; `ask()` waits for `$message->reply()` and ends with it, its timeout, its cancellation or `Contracts\Actors\NoReply`. Messages and replies are JSON, delivered at most once. With the local broadcast carrier an actor runs in the process that sends to it; with Redis, in the new `actors` server beside HTTP (`actors.workers` processes, each key in the one a hash picks), or on its own with `actors:work`. `ActorsProvider` is one of `App::PROVIDERS`. See [Actors](docs/actors.md).
- **Runs:** work of many steps that goes on from where it was after a crash, a deploy or a failure. A run is a class like a job whose `handle()` also takes `Contracts\Runs\Run`: `step()` keeps what it returns, `sleep()` and `await()` put the run aside without holding a worker, and `Runs::signal()` gives an await its value. Runs are kept in two tables, `runs:install` writes their migration, and queue workers carry them out on a renewed lease. A failed try is tried again `runs.tries` times after `runs.backoff`, from the step that failed; `runs:list` and `runs:retry` look after them. `RunsProvider` is one of `App::PROVIDERS`. See [Runs](docs/runs.md).
- **Streaming responses:** an action that returns a generator streams each value it yields as a server-sent event, at once; `Response::events()` does the same for any iterable, and `Response::stream($chunks, $type)` streams any other body. A slow reader makes the generator wait, a client that leaves stops it, and the response deadline now bounds a stream that stalls rather than one that keeps moving. `Testing\ApiResponse::events()` reads the events back. See [Streaming](docs/responses.md#streaming).
- **Streamed answers from the HTTP client:** `$http->stream()` takes what `request()` takes and returns once a successful answer's head arrives, its body read as it comes, a quarter of a megabyte ahead at most; dropping it or cancelling stops the request. `events()` reads an answer as server-sent events (`Contracts\HttpClient\Event`) and `lines()` line by line, on any answer. `FakeClient` streams too. A client of your own implementing `Contracts\HttpClient\Client` adds `stream()`, and a response of your own `events()` and `lines()`. See [Streaming answers](docs/http-client.md#streaming-answers).
- **A guide to AI applications:** when to stream, when to use a job, a run or an actor, and how they fit together. See [AI applications](docs/ai.md).
- **Rows as records:** `->into(Order::class)` reads rows into readonly classes of your own, each promoted property's type saying how its column is read: `int`, `float`, `string`, `bool`, backed enums, `DateTimeImmutable`, `#[Json]` arrays, `#[ColumnName]` and `Contracts\Database\Cast`. The query selects the record's columns, a value is never quietly made another type, and the writing methods take records and write them back. See [Rows as records](docs/queries.md#rows-as-records).
- **Servers kept across reloads:** a server registered with `reloads: false` keeps running on its code through `reload`, and only `restart` and `stop` end it; under `start --daemon` it runs in a generation of its own apart from HTTP. A reload that would change what is held, or move the address, is refused and names `restart`. `status` and `describe` say which servers are held. See [Keeping a server across reloads](docs/plugins.md#keeping-a-server-across-reloads).
- **A failed download leaves nothing beside its path at once:** the partial file is removed as soon as the answer fails, where it was left until the exception was freed when `zend.exception_ignore_args` is off.
- **`start` lists only the servers running:** a server switched off in `server.with` is no longer printed as `off`; `php cua describe` still lists every server registered with whether it is on.
- **Downloads and a limit on every answer (breaking):** no answer's body may be longer than `http_client.max_bytes`, 64 MiB by default, checked as it arrives, compressed and decompressed alike; a longer one throws `HttpClient\TooLargeException` and its connection is closed. Raise the limit for one call with `request(..., maxBytes:)`, or for the client with the setting or the constructor's `maxBytes:`. `sink:` streams the body of a `2xx` answer into a file that appears only once it is all there, or into a writable stream; `decode: false` keeps a compressed body as the server sent it. `FakeClient` does the same, and takes `maxBytes:`. A transport of your own takes a fifth argument to `exchange()`. See [Downloading files](docs/http-client.md#downloading-files).
- **Services that cannot be made are found before a server starts:** `start`, `reload`, `queue:work`, `schedule:work` and every runner follow what each route's action and named middleware, every listener and every scheduled task, job and command needs from the container, without making any of it, and refuse to start with every problem at once (`Contracts\Container\MissingServices`). A reload that would have failed on its first request now leaves the old server serving. `php cua describe app` lists the same problems. `Container::problem($id)` says why one entry cannot be made, and `App::unmade()` lists them all. See [Services that cannot be made](docs/deployment.md#services-that-cannot-be-made).
- **`status` and `stop` work when the application cannot be loaded:** after a deploy of code with a syntax error or a provider that throws, they act on the server in the background from the files in `storage/`, and every other command says why the application did not load and that the server goes on serving. `--pid` names a pid file other than `storage/crab.pid`. To have this, change the last line of `cua` to `exit(Crab\Cua::run(__DIR__ . '/app.php', array_slice($argv, 1)));`. `Server`'s `pidFile()`, `logFile()`, `statsDirectory()`, `stats()`, `running()`, `stop()` and `given()` moved to `ServerFiles`, which `$server->files()` returns. See [When the new code does not load](docs/deployment.md#when-the-new-code-does-not-load).
- **`describe` labels each problem `problem:`** where it said `does not fit:`, since a problem may now be a service as well as a setting.
- **A readiness recipe:** [Ready for traffic](docs/deployment.md#ready-for-traffic) keeps a probe that asks the database and the cache apart from `/up`, so an outage takes servers out of rotation without restarting them.
- **A running job keeps its reservation:** the worker renews it every third of `queue.retry_after`, so no other worker is given a job that is still running however long it takes, and `retry_after` now bounds only how long a job may block its process. A store of your own implements `renew()` (`Contracts\Queue\Store`).
- **Job timeouts:** `queue.timeout`, a supervisor's `timeout` or `#[Timeout(seconds: 1300)]` on the job bounds one try. When it is up, the `Cancellation` a job's `handle()` takes is cancelled and the try fails with `Contracts\Queue\TimedOut`; a job still running `queue.grace` seconds later has its worker's process ended and replaced. `Worker::deadline()` is the engine's part of that, for any work that must not outlive a limit. See [A job that takes too long](docs/queues.md#a-job-that-takes-too-long).
- **Cursor pagination:** `cursorPaginate($perPage, $cursor)` returns a `Contracts\Database\CursorPage` with the rows after the cursor and `nextCursor` for the page after them, as JSON `data`, `per_page`, `next_cursor`, `has_more`. Rows added or removed meanwhile do not shift the pages, nothing is counted, and the order may be by several columns, an alias of an expression or a grouped column, each in its own direction, with nulls where the database sorts them. An order that does not end with a unique column is refused; a cursor not given for the order is `Contracts\Database\InvalidCursor`, a `422`. See [Cursor pagination](docs/queries.md#cursor-pagination).
- **`Contracts\Http\HttpError`:** an exception that carries the status it is answered with. `HttpException` is one; the error handler answers any of them with its status and message, so a component that must not depend on HTTP can still mark a client's mistake. An error handler of your own should test for `HttpError` where it tested for `HttpException`.
- **Subqueries:** another query stands for a column with `selectSub()`, a condition with `whereExists()` and `whereNotExists()`, a value with `where('price', '>', $query)`, a table to join with `joinSub()` and `leftJoinSub()`, and the table read with `$db->table($query, 'name')`. It may name the outer query's columns, and its values are bound in place. `groupByRaw()` groups by an expression. `Connection::table()` takes an alias, `table('users', 'u')`; a connection of your own adds `?string $as = null`. See [Subqueries](docs/queries.md#subqueries).
- **JSON columns are read at a path** wherever a column is named, `where('data->actor->id', $id)`, with a missing key and JSON's `null` alike to `whereNull()`, and `true` and `false` compared as JSON's. See [JSON columns](docs/queries.md#json-columns).
- **Presence and null are apart (breaking):** as in PHP, a field without a default must be sent, even when its type is nullable: `?string $note` is required and may be null, `?string $note = null` may be left out. In `#[Fields]`, a name ending in `?` may be left out and a type starting with `?` may be null, apart: `'name?' => 'string'` may be left out but never cleared, which is what an update wants. An object or a list described in place is never null. To upgrade, give a nullable field that may be left out a default, `= null`, and in a description move a `?` that meant "optional" to the end of the name.
- **`#[RejectUnknown]`** on an input class, or on described `Data`, refuses a field it does not declare with `is not expected`, where Crab otherwise ignores it. See [Refusing unknown fields](docs/validation.md#refusing-unknown-fields).
- **Rules across fields:** an attribute that implements `Contracts\Validation\ObjectRule`, on a class or on described `Data`, checks the object once its fields are valid and names the field a problem is told against. See [Rules across fields](docs/validation.md#rules-across-fields).
- **A value of several kinds:** a field may be a union of scalar types, `bool|int|string|null`, taken as JSON says; text stays text where `string` is one of them. See [A value of several kinds](docs/validation.md#a-value-of-several-kinds).
- **Each action parameter says where it comes from (breaking):** a plain parameter is a parameter of the path, `#[FromQuery]` (`Crab\Routing\FromQuery`) reads the query string, field by field or as one marked class or described `Data`, and a class or described `Data` without the mark is the body. A body's field is no longer a parameter of its own, and the query string is no longer read in place of the body on `GET`, `HEAD` and `DELETE`, so a field cannot come from the address when the action meant the body. A signature that leaves a source unsaid is refused when the route is added, with what to write instead. To upgrade: mark query fields `#[FromQuery] int $page = 1`, and move a body's fields into an input class or `#[Fields([...])] Data $input`; on a `GET`, mark an input class `#[FromQuery]`. A validation `422` now says where each problem was: `fields` for the body as before, `query` and `path` beside it; `Problem` and `ErrorResponse::make()` take `query:` and `path:`. See [What an action takes](docs/actions.md#what-an-action-takes).
- **`cache:clear` keeps locks:** `clear()` removes this cache's values only, on every store, and leaves its locks and every other `cache.prefix`'s entries. `cache:clear --locks` (`clearLocks()`) also frees locks, for one left by a process that died. Values and locks now live under `value:` and `lock:` keys, and the file store keeps each entry's key, so entries written by an earlier version are read as missing once: the cache starts empty after the upgrade. A store of your own implements `extendIf()` and `clear(string $prefix)`.
- **Locks can be refreshed:** `$lock->refresh($ttl)` holds a lock longer, only while it is still yours, for work whose length you cannot know.
- **`withoutOverlapping()` for scheduled tasks:** a run is not started while another runs on any server, or in the generation a reload replaces. It holds a lease renewed while the run lasts. `onOneServer()`'s claims are locks now, so clearing the cache no longer gives a run to a second server. See [Overlapping runs](docs/scheduling.md#overlapping-runs).
- **Uploads are fields of the body:** declare a file as `public UploadedFileInterface $avatar` in the body's input class, or in described `Data`, and it is checked before the action runs: required unless nullable, an empty file input counting as none, `#[FileSize]` for its bytes and `#[MediaType]` for its kind, read from the content. `#[ListOf(UploadedFileInterface::class)]` takes `photos[]`, and `describe` shows them. See [Uploaded files](docs/requests.md#uploaded-files).
- **The test client sends forms, files and raw bytes:** `Testing\Api`'s `post()`, `put()`, `patch()` and `request()` take `form:`, `files:` and `body:` as the HTTP client does, through the same parser a client's request meets. See [Testing](docs/testing.md#sending-forms-files-and-raw-bytes).
- **File storage:** named disks behind `Contracts\Storage\Disk`, with `local` (the folder `storage/files`, by default) and `memory` for tests. A file is written whole or not at all, read as a stream, listed a page at a time, copied and moved; a path is checked before a disk is touched. `crabphp/s3` adds `s3`, for Amazon S3, Cloudflare R2, MinIO and the rest, on the HTTP client, with signed download and upload URLs. See [File storage](docs/storage.md).
- **Your own error format:** bind `Crab\Contracts\Http\ErrorRenderer` and it writes every error response, returned or thrown: the router's 404 and 405, validation's 422, middleware's 401, 429 and CORS refusals, `HttpException` and a failure's 500, keeping the headers middleware gave them. Replacing the error handler is no longer needed to change the format. `ErrorResponse::make()` takes `cause:` and `debug:` in place of `$detail`.
- **`text()` and `binary()` hold any length on MySQL,** as documented: they create `longtext` and `longblob`, where `text` and `blob` stopped at 64 KB. Tables already created keep their columns; change one with a migration of its own if it needs more.
- **The testing guide's database settings** now match the skeleton (`DB_DRIVER` and `DB_DATABASE`, not `DB_DSN`, which nothing read), and the skeleton's `phpunit.xml` sets them, so tests never reach the development database.

## 0.1.0 — 2026-10-24

The first public release: a long-running JSON API framework with its own engine.

- **Server:** `dev` serves and restarts when a file is saved; `start` serves for production, in the foreground or with `--daemon` in the background, where `reload` replaces it without refusing a connection, keeping the options it was started with. `status` shows every running server, its workers and what each has handled.
- **Settings** are checked when the application starts, against rules declared beside their defaults; every problem is said at once, and `describe app` lists them.
- **Routing, actions and validation** from typed parameters, PSR-7 and PSR-15 middleware, errors as JSON, logging, authentication, cache, events, queues, scheduling, an HTTP client, database queries and migrations, WebSockets and broadcasting.
- **`describe`** prints the whole application for coding agents.
